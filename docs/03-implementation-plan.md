# 实现路线与验收清单

菜单栏连接与取地址、主窗口配置与排障的分工已确认。首版提议同时覆盖自己创建的隧道与本机已有的外部 SSH 转发。用户可以在同一个菜单中使用两者。[外部发现的覆盖范围](02-product-design.md#本机发现)

界面实现对照 [UI v2](04-ui-v2.md) 的画板、尺寸和动效。菜单栏保留连接和复制的简短路径，主窗、编辑器和首次使用共享三种转发的路径组件。

## 首版边界

| 优先级 | 范围 |
| --- | --- |
| 首批可用路径 | 双栏主窗、菜单栏面板、单页编辑器、SSH 别名、密钥或 ssh-agent、首次指纹确认、本地转发、端口冲突修正、配置持久化，以及本机已有 OpenSSH 本地转发的只读发现与复制。 |
| 首版完整能力 | 同一隧道的多条规则、远程和 SOCKS 转发、等待凭据与取消、可选记入钥匙串、手动断开、逐步延长等待间隔的自动重连、诊断以及选择性导入 SSH 配置。现有别名的跳板机设置交给 OpenSSH 解析。 |
| 后续按需求安排 | 独立代理编辑界面、旧客户端格式迁移、智能分组和批量操作。 |

## 技术选择

- **界面。** 部署目标为 macOS 14，使用 SwiftUI 的原生窗口、`MenuBarExtra` 和 Sheet。主窗用内嵌侧栏实现 v2 的窗口留白和圆角。主窗口及菜单栏绑定同一份隧道配置与运行状态。关闭主窗后维持连接，退出应用时结束它管理的 SSH 进程。
- **复用顺序。** 固定上游提交，先引入需要的规则模型、参数构建、校验、日志解析和相应测试，把 MIT 许可与被复用源码一并登记。再接入进程、askpass、钥匙串和网络事件。上游运行时直接依赖管理器与凭据提示，首轮只替换与新宿主之间必要的接点。[上游包结构](https://github.com/bryan31/porthole/blob/e6fa8c263798f71d1b98c4993051665b68d18800/Package.swift) · [上游运行管理](https://github.com/bryan31/porthole/blob/e6fa8c263798f71d1b98c4993051665b68d18800/Sources/Porthole/Engine/TunnelManager.swift#L19-L49)
- **连接与转发确认。** 启动系统 OpenSSH 主进程，通过现有 SSH 别名解析认证和跳板。主进程使用 `ClearAllForwardings=yes` 和私有控制套接字，随后逐条用 `ssh -O forward` 申请 Lane 的规则。所有规则得到确认后才显示“已连接”。因此即使 SSH 别名包含 `LocalForward`，也可以在 Lane 单独管理选中的规则。诊断里的 SSH 命令用于查看配置中的连接参数和规则。[OpenSSH 客户端手册](https://man.openbsd.org/ssh.1)
- **故障定位。** 已知端口冲突的事件携带规则 ID、监听端口和可选的占用进程名。界面据此打开对应编辑字段。其他失败先保留原始诊断，再按有证据的类别给动作。改名称或备注时只刷新展示，改主机、认证或规则时重连该隧道。[上游现有的变更处理](https://github.com/bryan31/porthole/blob/e6fa8c263798f71d1b98c4993051665b68d18800/Sources/Porthole/Engine/TunnelManager.swift#L134-L138)
- **数据。** 为新产品使用独立的应用标识、Application Support 目录及钥匙串 service。隧道和规则沿用稳定 ID，配置写入 JSON。由用户发起 SSH 配置导入，预览后写入新产品的数据目录。首次启动由用户选择要连接的隧道。[上游存储行为](https://github.com/bryan31/porthole/blob/e6fa8c263798f71d1b98c4993051665b68d18800/Sources/Porthole/Engine/TunnelStore.swift#L109-L178)

### 外部会话的只读发现

1. 打开菜单栏、主窗重新激活或用户点刷新时，取当前用户可见的 OpenSSH 进程和 TCP 监听快照。先筛选 SSH 进程，再读取所需启动参数，只提取主机与转发字段。完整命令行和环境变量均不写入日志或持久化存储。
2. 按进程归属关联监听的地址族、绑定地址和端口，再匹配 `-L`、`-D`、`-R` 及能明确解析的等价参数。匹配 `-L`、`-D` 时必须同时有该进程的监听证据。端口相同而地址或进程不同的记录不能合并。参数缺失时保留能确认的监听，远端声明单独标注。
3. 按运行中的 SSH 进程分组。同一主机有两个独立进程时保留两组，同一进程下的多条规则则共用一行隧道。排除 Lane 当前拥有的子进程，外部条目不进入受管运行时、配置文件或退出清理清单。
4. 本轮在普通用户会话里，用 `ps` 的 SSH 启动参数与 `lsof` 的监听记录交叉验证了“一条外部连接、两个本地转发”。产品实现后还需用实际签名和权限配置验证相同可见性。验收样例使用虚构主机与端口。[OpenSSH 手册](https://man.openbsd.org/ssh.1) · [lsof 手册](https://lsof.readthedocs.io/en/latest/manpage/)

## 实施与验收

| 阶段 | 交付 | 可以验收的结果 |
| --- | --- | --- |
| 1 · 原生界面 | 用示例数据实现 v2 主窗、菜单栏与表单，完成三种路径和首次使用引导。 | 从已打开的菜单栏复制单规则入口只需一次点击，多规则隧道最多再展开一次。切换 `-L`、`-R`、`-D` 更新端口字段、方向和用途说明，保留名称、SSH 主机与自定义备注。以实际 Mac 窗口核对浅色、深色、键盘顺序和收窄布局。 |
| 2 · 本地转发与发现 | 接入 OpenSSH、认证、保存、断开和外部监听快照。 | 在受控 SSH 主机验证受管入口可用。在同一菜单复制另一个 SSH 进程的本机入口。关闭主窗后两者均可使用，退出 Lane 只释放受管监听。 |
| 3 · 完整转发与恢复 | 多规则、本地 SOCKS、远程确认、端口冲突和重连。 | 一条本地规则与一条远程规则共用一个 SSH 进程。SSH 服务器上可通过其监听端口访问约定目标。SOCKS 客户端可经本地代理访问测试服务。冲突仅定位到对应规则，编辑后可恢复。网络恢复后仅重连仍要求开启的隧道。 |
| 4 · 导入与首次分发准备 | 导入预览、中英文基本文案、发布材料和来源登记。 | 从样例配置导入所选的具体 Host 与转发，核对实际监听条数。对于已有转发的同名 SSH 别名，验证配置与显式参数组合时的实际行为。公开前再确定名称、自有许可和分发方式。 |

### 需要真机走一遍的场景

- [ ] 首次连接主机时显示可核对的指纹，取消后连接结束。已记录的主机指纹发生变化时停止并解释原因。
- [ ] 开两个隧道，其中一个端口被占。修复该端口时，另一个隧道的客户端连接持续可用。
- [ ] 提前启动一个有两条 `-L` 的外部 OpenSSH 进程。首次启动 Lane 就能找到一条外部会话、展开两个入口，并从菜单栏分别复制。用端口搜索可定位该会话。Lane 的受管连接只显示一次。
- [ ] 退出 Lane 后外部 SSH 仍在监听。从原工具结束该会话后刷新，条目随之消失。只读到 SSH 监听且未知目标时仍列出入口。纯 `-R` 声明标为“远端未核实”。
- [ ] SSH 与转发均已建立，但后方测试服务停机。界面仍准确描述监听状态，避免显示“数据库健康”等未经检测的结论。
- [ ] 休眠与唤醒后验证期望开启的隧道。等待重连时手动断开，再恢复网络，保持断开。
- [ ] 全键盘从搜索到复制、VoiceOver 读出方向和所属机器、减少动态效果、长别名及窄窗口均可操作。关闭主窗后可从菜单栏重新打开。
- [ ] 路径动画表现连接发起方向。远程转发从服务器端起步，动态转发按次切换示例目标，断开和只读外部会话保持静态。复制入口仍可在规则列表与菜单栏直接触达。

## 本地实现与验收

- SwiftPM 负责构建，`scripts/build-app.sh` 组装本地 `.app`。上游复用来源固定为 `bryan31/porthole` 的 `e6fa8c263798f71d1b98c4993051665b68d18800`，包含核心模型、参数、导入、日志、askpass、部分运行时和对应测试。窗口、菜单栏和转发图按 v2 独立实现。[上游 MIT 许可](Porthole-MIT.txt)
- `swift test` 运行纯逻辑测试。`scripts/test-loopback.py` 连同回环用例共通过 45 项。回环用例覆盖真实 `-L`、`-R`、`-D`，首次主机指纹的转发、拒绝和接受，已信任指纹变化后的拒绝，以及配置保存、仅修改备注、端口冲突、重连与取消、外部会话分组。测试侧 SSH 和 HTTP 服务绑定回环地址。
- Debug 构建可用 `.build/Lane.app/Contents/MacOS/Lane --render-previews .build/visual-review` 输出原生主窗、深色、窄窗、三种编辑状态及菜单栏的示例截图。实际菜单栏鼠标操作、VoiceOver、真实睡眠唤醒和其他 macOS 版本仍待验收。
